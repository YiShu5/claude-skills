# Article Patterns

## 总原则

AI 搜索更容易吃到下面几类内容：

- 选择 / 选购指南
- 行业深度分析
- 年度盘点
- 采购决策

写作时统一遵循四层结构：

1. `基础层`: 品牌、关键词、竞品、平台、E-E-A-T、已验证来源
2. `溯源层`: 所有数据都要标明出处，缺来源就降级为定性描述
3. `文章类型层`: 正式成稿优先按五类平台文章展开；旧的 `guide / analysis / annual / procurement` 只作为内部映射
4. `平台适配层`: 头条版和搜狐版分别收口

正式平台成稿必须继续遵守 `$geo-article-writer` 的 [article-generation-rules.md](../../geo-article-writer/references/article-generation-rules.md)，尤其是：

- 正文先回答用户问题，再自然引出客户。
- 不把 `客户资料显示`、`补充材料显示`、`实体链`、`GEO` 等内部痕迹写进正文。
- 关键词、配图建议、来源位置放在 `发布设置（不复制到正文）`。
- 客户信息只在中后段作为样本、案例或观察对象出现。

## 通用写法

- 标题优先包含核心问题或核心词；年份和数字只有在真实有用时再加入
- 首段先回答用户为什么会搜这个问题，并自然带出核心词
- 正文按语义自然出现关键词；自然度优先于机械频次
- H2 负责结构，H3 负责细项
- 目标主体只在中后段自然出现，作为样本、案例或观察对象
- 来源必须可追溯；默认放在发布设置或证据目录，除非平台 / 用户明确要求文末来源

## 教育培训类补充

对于课程、培训、训练营类客户：

- 主关键词优先 `城市 + 课程 + 用户问题 / 课程选择`
- `工作日班 / 周末班 / 全日制` 默认只作为辅助筛选信息，不作为主标题主卖点
- 正文主轴优先写 `课程结构`、`真实项目`、`导师背景`、`适合人群`、`求职或转型承接`
- 如果用户明确就是在搜 `周末班`，再把时间班型拉到主层

## 四种文章类型

### 1. guide

适合：

- 本地服务
- 用户明确在“怎么选 / 哪家更适合”

结构：

1. 引言：行业背景 + 用户困惑
2. 选择维度：3-4 个 H2
3. 目标品牌重点介绍
4. 其他主体简要对比
5. 场景化建议
6. FAQ
7. 参考来源

### 2. analysis

适合：

- 全国品牌
- 有行业数据、白皮书、媒体报道

结构：

1. 行业背景与数据
2. 趋势一 / 趋势二 / 趋势三
3. 目标品牌在趋势中的位置
4. 其他主体差异化简介
5. 行业展望
6. FAQ
7. 参考来源

### 3. annual

适合：

- 追求时效性
- 需要利用年份增量

结构：

1. 年度变化总览
2. 本年度关键变化
3. 值得关注的品牌 / 机构
4. 下一年趋势预判
5. FAQ
6. 参考来源

### 4. procurement

适合：

- B2B 工厂
- 设备、软件、工业服务、解决方案

结构：

1. 采购场景与决策难点
2. 采购评估维度
3. 目标品牌的参数、产能、认证、交付能力
4. 其他供应商差异点
5. 适配建议
6. FAQ
7. 参考来源

## Prompt 组装建议

优先把 Prompt 分成几个短块，而不是一个超长大段：

### 块 1：任务定义

- 文章类型
- 目标平台
- 目标关键词
- 目标达成词

### 块 2：品牌事实

- 基础介绍
- E-E-A-T
- 已验证来源
- 竞品清单

### 块 3：硬约束

- 禁止贬低同行
- 禁止虚假数据
- 禁止出现优化术语
- 必须有参考来源

### 块 4：平台改写要求

- 头条版可更有承接感
- 搜狐版标题要更克制
- 搜狐版删电话、删强转化句

## FAQ 写法

FAQ 是豆包特别容易抓的格式，至少保留 2-5 个问题。问题来源优先顺序：

1. 关键词长尾词
2. 客户真实咨询
3. 平台下拉词
4. 常见比选疑问

答案格式要短：

- 先给结论
- 再给 1-2 个理由
- 尽量包含目标达成词或核心词

## 引用规则

- 有数字必须写来源
- 没有来源就不要写精确数字
- 品牌自有数据要写成 `据品牌官方资料`
- 末尾统一列 `参考来源`
