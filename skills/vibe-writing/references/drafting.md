# Drafting

Use this reference for new content. Let the requested genre and register govern
the result; do not convert every request into one public-account voice.

## Sequence

Follow this sequence:

```text
classify request
→ assemble task, profile, confirmed material, and required sources
→ ask only for a material gap
→ form a structure without a mandatory approval gate
→ draft in the requested register
→ run factual and quality checks
→ deliver the draft plus only necessary notes
```

## Classify and Assemble

Identify the artifact, audience, purpose, platform, scope, register, and delivery
format. Gather only inputs relevant to the task:

- The current instruction and constraints.
- A project voice profile or real samples when voice fidelity matters.
- User-confirmed facts, experiences, quotations, and source material.
- Current authoritative sources when claims are time-sensitive or uncertain.

Do not create a project profile or workspace merely because neither exists.

## Resolve Only Material Gaps

Ask one focused question only when the missing answer would materially change
the thesis, audience, use of personal experience, key factual basis, or handling
of a profile conflict. If the remaining ambiguity is minor, choose the smallest
reasonable assumption and continue.

Form an internal working structure and draft directly. Request outline approval
only when the user asks for staged collaboration or when a material choice truly
cannot be resolved from the request.

## Match the Register

Support each format on its own terms:

| Format | Adapt to |
|---|---|
| Public-account article | Platform reading flow, audience familiarity, and the requested editorial tone |
| Blog | The author's purpose, depth, and chosen personal or professional register |
| Newsletter | Recurring audience relationship, issue format, and information density |
| Professional analysis | Precise claims, explicit reasoning, calibrated uncertainty, and formal tone |
| Product or technical content | Correct terminology, user goal, examples, and operational clarity |
| Social post | Platform constraints, concise context, and a proportionate call to action |

Do not impose slang, emotional intensity, first-person anecdotes, fixed sentence
lengths, a stock opening, or a shared structure across these formats.

## Check and Deliver

Use fact checking for personal claims, unstable external claims, or unsupported
key facts. Use the quality rubric to check hard gates and the dimensions relevant
to the task. Fix problems without flattening deliberate voice features.

Deliver the requested draft. Add sources, assumptions, or unverified items only
when needed to interpret or safely use it. Do not add images, distribution
plans, alternate titles, or extra assets unless requested.
