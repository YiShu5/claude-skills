# 运行示例（演示用，非真实证据）

展示一次完整运行：输入 → 单次追问 → V1 → 人工纠错 → V2。参赛投稿的真实证据须来自用户本人真实工作记录。

## 场景：从会议记录提取个人日报

**用户输入**

> 我是黄超，今天9月10日。这是昨晚项目会的记录，帮我整理我的日报。
>
> （附会议记录片段）
> 新版注册页下周上线，后台接口本周五提测；支付风控两版方案还没定；注册页数据埋点跟着上线一起做；黄超负责 AI 文案工具，先做笔记拆解仿写，找对标后面再做；另外要把封面图转成提示词发豆包试试能不能生成同类图。

**Skill 的追问（一次只问一个最影响结果的问题）**

> 待确认：AI 文案工具首版今天处于什么状态——已启动开发、还是待启动？期望什么时候交付？这决定它进 ✅ 还是 🚶。

**用户补充**

> 已在开发，首版下周一（9月14日）交付；图片转提示词还没开始，时间待定。另外抓对标示例表格今天同事已经发给我了。

**V1 输出**

```
9月10日工作总结
✅：
1、收到抓对标示例表格（同事交付），需求对齐材料已就绪。
🚶：
1、AI 文案工具首版（笔记拆解仿写能力）开发中，计划9月14日（周一）交付，找对标能力后续再排期。
2、封面图转提示词发豆包验证生成路径，待启动，完成时间待确认。
明日计划：
1、跟进拆解仿写首版开发排期，确认联调节点。
2、确定图片转提示词验证的完成时间。
```

> 请逐条核对完成状态、结果数据和明日计划，确认无误后再发送。

**人工纠错指令**

> 第2条 🚶 删掉，图片验证我明天上午先做一版，放到明日计划第1条。

**V2 输出（仅改涉及项，其余不变）**

```
9月10日工作总结
✅：
1、收到抓对标示例表格（同事交付），需求对齐材料已就绪。
🚶：
1、AI 文案工具首版（笔记拆解仿写能力）开发中，计划9月14日（周一）交付，找对标能力后续再排期。
明日计划：
1、上午完成一版封面图转提示词，发豆包验证同类图生成可行性。
2、跟进拆解仿写首版开发排期，确认联调节点。
```

## 边界说明

- 输入中没有任何已完成事项时，✅ 区保留并写"无"，不把进行中事项提前。
- 他人的待办（如"接口本周五提测"，负责人不是用户）不进个人日报，除非用户本人对其负有跟进责任且在输入中有依据。
- "下周上线""尽快"这类模糊时间不写成具体日期；用户确认后再落日期，否则保留原表述或标"待确认"。
