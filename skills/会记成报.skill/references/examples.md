# 运行示例（演示用，非真实会议证据）

以下示例展示一次完整运行：输入 → 单一追问 → V1 → 人工纠错 → V2 → 周报合并。用于说明输出形态与纠错闭环，参赛投稿的真实证据须来自用户本人真实会议。

## 场景一：单场会议 → 纪要 + 日报 + 素材卡

**用户输入**

> 我是张三，会议日期是9月10日。请整理会议纪要，并提取我的日报。
>
> （附转写稿片段）
> 李四说新版注册页下周上线，王五负责后台接口，说这周五提测。张三你说的是那个支付风控的优化吧，这个我们讨论过两版方案，还没定用哪个。李四补充：注册页数据埋点要跟着做。散会前王五说接口接口联调好像有个问题，要再看一下。另外下周还有个大促复盘会，时间待定。

**Skill 的追问（一次只问一个最影响结果的问题）**

> 待确认：注册页上线是"已完成"还是"进行中"？"下周上线"指什么日期？这会影响待办状态和截止时间的标注，请补充。

**用户补充**

> 注册页还在开发中，计划9月15日上线。接口提测是本周五，即9月12日。

**V1 输出**

## 场景二：周五合并周报

**用户输入**

> 这是本周已确认的日报（9月10日、9月11日），请按事项合并本周进展，去掉重复描述，生成周报；未确认内容不要写成完成。

**Skill 输出**

```
本周工作进展
1、注册页改版：9/10 确定上线日期9/15、后台接口9/12提测；9/11 接口联调问题已定位并修复，注册页进入上线前验证（进行中）。
2、支付风控：确定采用B版方案，完成方案拆分，评审排期待确认（进行中）。
下周计划
1、注册页9/15上线，完成验收与数据埋点核对。
2、完成支付风控B版开发排期并启动。
```

> 请逐条核对事项、负责人、完成状态、数据和计划，确认无误后再发送。

## 说明

- 素材卡与日报中，只有用户明确确认过的内容才可作为"已完成"证据。
- 同一事项跨多天出现时，只保留本周新增进展，不重复累计相同描述。
