# 方片面聊转写导出（fangpian-facechat-export）

把一场企业微信面聊的转写，整理成会议纪要系统能直接读的固定格式 Markdown。系统每晚把它对上会议室录音那场会，换成**带发言人真名**的转写，纪要、卡点、待办就能写到具体的人。

**格式是系统按行读的，一个字段都不能改名、不能多加内容。**

## 一、哪些不导出

遇到下面这些，直接告诉用户「这场不导出」并说明原因，不生成文件：

- 面试、谈薪酬、绩效面谈、辞退沟通这类人事会议；
- 用户说这场是私人谈话、不想进系统的。

## 二、文件名

`日期_开始时间_会议标题.md`，例如 `2026-10-22_2130_AI商业化与创新机制.md`。

- 开始时间 4 位数字，不带冒号；
- 标题里的 `/ \ : * ? " < > |` 换成 `-`。

## 三、文件内容（严格按这个格式）

不要加别的标题、说明、总结、表格：

```markdown
# 会议标题
- 日期：YYYY-MM-DD
- 时间：HH:MM–HH:MM
- 会议室：开会的会议室名字
- 发起人：发起人姓名
- 参会人：姓名、姓名、姓名

## 转写
[HH:MM:SS] 姓名：这句话的原文
[HH:MM:SS] 姓名：这句话的原文
```

- **会议室**：写开会所在会议室的名字，例如 `2F 正心正念`；不在会议室、纯线上就写 `线上`；不知道就先问用户，不要猜。
- **时间**：面聊开始到结束，用 `–` 连接。

## 四、转写部分的规则

1. 一句一行，按时间先后；时间是这句话开始说的时刻，精确到秒。
2. 「姓名」用企业微信里的显示名，可以带括号花名，例如 `于静平 (吉米)`；不知道是谁说的写 `未识别`，**不要猜**。
3. 原文照抄：不改写、不总结、不润色、不删减，口头语和错字也保留；听不清的地方写 `[听不清]`。
4. 不要给转写加任何评论或标注。

## 五、存好以后

存进微盘文件夹「会议系统·面聊转写」，然后告诉用户：

- 文件名、一共多少句、几位发言人；
- 如果会议室是 `线上` 或不确定，提醒一句：「这场对不上会议室录音，系统会先记下来，不会进当天的会议纪要」。

## 示例

```markdown
# AI商业化与创新机制
- 日期：2026-10-22
- 时间：21:30–22:40
- 会议室：2F 正心正念
- 发起人：刘毅凯
- 参会人：于静平、张振东

## 转写
[21:54:03] 于静平 (吉米)：你去尝试怎么跟他聊，什么样的博主可以破冰。
[21:54:10] 张振东：理论上，财务不需要吧？
[21:55:02] 于静平 (吉米)：好哥已对接财务。
```
